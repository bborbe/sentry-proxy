# Tee the request path: single publish call site, body buffering, error isolation

<summary>
- Every request the proxy receives on the ingest path now results in exactly one non-blocking Kafka enqueue, from a single call site after the outcome is known — never two, never zero on the reject or upstream-error paths
- The request body is buffered once before any forwarding decision and restored, so both the Kafka record and the upstream forward carry the full bytes; a rejected alert is no longer logged-then-lost
- A Kafka publish failure is counted and logged but can never change, delay, or fail the HTTP response, so a broker outage cannot take down Sentry forwarding
- An upstream failure is recorded in the record's `outcome` (`upstream_error`) instead of suppressing the publish
- The record's `project` is derived from the ingest path (`/api/{project_id}/…`) and falls back to `unknown` for non-matching paths
- A stalled Kafka sender no longer stalls the request path — the round tripper only enqueues, the worker owns the broker wait
</summary>

<objective>

This completes the tee (spec DB2, DB4, DB5; AC1-AC5, AC11 latency clause).
</objective>
